# Проверка JBL WAN — исследование Juri

**Juri (Juri-Halveth) · 27 ноября 2026 года**

**[Полный отчёт и материалы](https://github.com/Juri-Halveth/jbl-owner-external-witness-20260901/blob/main/REPORT.md)** · [Обзор на русском](https://github.com/Juri-Halveth/jbl-owner-external-witness-20260901/blob/main/README.ru.md)

Запускаемый вручную workflow пытается установить TCP-соединение с заданным адресом на порту 57120. При успешном соединении он отправляет запрос WebSocket Upgrade и читает первую строку HTTP-ответа. Статус 101 сам по себе не подтверждает полный WebSocket-handshake или принадлежность сервиса JBL. Формулировки исправлены в [PR #2](https://github.com/Juri-Halveth/jbl-wan-proof/pull/2).

Журналы двух августовских запусков 27 ноября возвращали HTTP 410. Workflow может завершиться с кодом 0 даже при неудачном подключении. Поэтому зелёный статус Actions не доказывает сетевую доступность.

В соседнем репозитории сохранены отдельные сентябрьские результаты: изменение и восстановление значения **75 → 74 → 75** через туннель владельца с предоставленными данными сопряжения, а также прямая TCP-проверка, завершившаяся тайм-аутом. Полный отчёт указывает условия опытов, отсутствие точной версии продукта и непроверенный текущий статус исправления. Новые сетевые испытания при подготовке публикации не выполнялись.
