## Роль этой проверки

Здесь сохранён дополнительный опыт с внешним TCP/HTTP-доступом. **Основное сообщение касается локального IPC: процесса Windows без повышенных прав и повторного использования существующего состояния сопряжения.** Оно не сводится к вопросу доступности сервиса из Интернета.

**24 сентября 2026 года** CERT@VDE передал подтверждение инженерной команды: проблема проверена, **QuantumENGINE 2.7.8** затронута, предложенная оценка серьёзности принята. Числового балла в предоставленной переписке нет. Исправляющее обновление тогда планировалось на **декабрь 2026 года**; это исторический план, а не подтверждение выпуска исправления.

**19 октября** CERT@VDE сообщил, что HARMAN не признал заявку соответствующей критериям вознаграждения в своей программе bug bounty, и отдельно подтвердил будущее указание Juri как автора находки. **Последний предоставленный ответ не датирован** и следует за обменом от 22 октября: бюллетень ещё не опубликован, конкретной даты нет. Ссылки на бюллетень и CVE обещаны после публикации; сам идентификатор CVE в тексте отсутствует.

## Как понимать сетевые результаты

Workflow пытается подключиться по TCP к порту **57120** и при успешном соединении отправляет запрос WebSocket Upgrade. Одна строка HTTP 101 не подтверждает полный handshake или принадлежность сервиса JBL. Журналы двух августовских запусков при проверке возвращали HTTP 410. Зелёный статус Actions не доказывает доступность: workflow может завершиться с кодом 0 после неудачного подключения.

В соседнем репозитории сохранены отдельные сентябрьские результаты: **75 → 74 → 75** через туннель владельца с предоставленными данными сопряжения, а также прямое TCP-подключение с тайм-аутом через **8009 мс**. Ограничения этих дополнительных опытов нельзя распространять на всё подтверждённое дело о локальном IPC.

Новые сетевые испытания при обновлении документации не проводились. Эти записи не определяют уязвимость или исправленность текущего выпуска.
